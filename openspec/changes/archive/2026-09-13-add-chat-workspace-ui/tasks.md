## Acceptance Criteria

| AC | Verifiable outcome |
|---|---|
| AC-01 | A widget-free, session-scoped application controller lists catalog chats/issues, creates/selects/restores exactly one repository-backed chat, closes without deleting, ignores stale completions, and restores acknowledged messages after fresh-stack restart; empty and failing catalogs are distinguished. |
| AC-02 | Stable titles are derived once from the first committed user text by configured whitespace/control/grapheme policy, survive compaction/restart, appear in catalog summaries, and legacy null titles use only the fallback; list order and post-delete next/previous/null selection are deterministic. |
| AC-03 | Workspace mutations use one typed command lane: incompatible create/select/send/switch/compact/delete/close races return busy or sanitized conflict without queueing hidden work, double-appending input, replacing newer state, or letting late results change the selected chat. |
| AC-04 | Current per-chat `{providerId, modelId, reasoningMode, effort}` validates against registry capabilities, initializes compatibly from legacy definitions, persists/restores exactly, freezes for each admitted run, applies only to subsequent runs, preserves historical model attribution, and exact no-op causes no estimate/save/revision/provider call. |
| AC-05 | A fitting target-model switch validates target-shaped context with the configured estimator/fit policy, strips only incompatible opaque continuation state, commits one successor before live adoption, and sends the next run with the target while leaving visible history and prior accounting unchanged. |
| AC-06 | An oversized target invokes the configured compactor with `modelSwitch` reason/target and commits valid candidate, provenance, accounting, continuation removal, and selection atomically; no intermediate compacted-old-selection record is observable. |
| AC-07 | Invalid target, busy state, missing compactor, no-change/ineffective candidate, cancellation, conflict, save failure, and process loss retain the old selection/visible history unless combined commit won; incurred compactor usage is finalized once under its actual model and never appears as assistant-response work. |
| AC-08 | Stop is idempotent and cooperatively cancels provider/tool/approval/automatic/model-switch work while retaining committed and visibly marked partial output. Delete requires identity-bound danger confirmation, stops/stabilizes/closes before expected-revision tombstone, reports no optimistic success, has deterministic neighbor behavior, and has no undo/secure-erasure claim. |
| AC-09 | Timeline projection merges persisted snapshots and live deltas by stable identities into user/assistant/reasoning/tool/compaction/error parts; snapshot replacement and configurable pacing preserve order, flush terminal content, and never duplicate/drop text or tool cards/results. |
| AC-10 | User and assistant bubbles are distinct; every reasoning block is independently collapsed initially; tool cards expose name/status/arguments/progress/committed result/outcome with plain-text fallback; compaction/errors are sanitized and never expose removed/generated/provider/credential/opaque content. |
| AC-11 | The composer has separate model and reasoning controls; model choices are grouped under registry-supplied provider headings, custom groups work without feature id branches, and mode/effort options/default fallback exactly follow each model's unsupported/optional/required capabilities and declared efforts. |
| AC-12 | Compact and detailed token UI reads `AgentTokenAccountingSnapshot` only and correctly distinguishes current/latest request, complete session/history including compaction/legacy, and latest committed response correlation across input/output/reasoning/cache read/write/hit/overall plus retained-context bound, provenance, partial/inconsistent/unavailable states without zero fabrication or double count. |
| AC-13 | `lib/design_system/**` is the single source for primitive/semantic theme, dimensions, spacing/radius/breakpoints/focus/components; production workspace/settings entry contain no raw visual constants or hard-coded provider/model/layout counts, and coherent dark-primary/light themes satisfy deterministic static/contrast checks. |
| AC-14 | At desktop width the UI matches the supplied Codex-style ~276 px sidebar, slim header, centered timeline, bottom calm pill composer and reference preview; narrow width uses drawer/list navigation with all actions retained. Fixed dark/light desktop/narrow goldens show no clipping at 200% text scale. |
| AC-15 | Keyboard/semantics expose Enter send, Shift+Enter newline, primary+N new chat, primary+comma settings, Escape dismissal, deterministic focus return, 44×44 targets, bounded live announcements, stable test keys, reduced motion, reachable settings/missing-key action, and no excluded feature claims. |
| AC-16 | Production uses durable sessions and configured OpenCode summary compaction rather than one-shot prompts; fresh JSONL restart, full tests/goldens, `dart format .`, `flutter analyze`, Linux build, web build, strict OpenSpec validation, diff/static path checks, and a final whole-requirement AC-01–AC-16 review pass on one frozen integrated tree. |
