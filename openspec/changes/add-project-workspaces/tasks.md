## Acceptance Criteria

- **AC-01 — Project model:** Strict Project v1 tests distinguish desktop external and mobile sandbox roots; identity, normalized unique name, legal additional references, revisions, timestamps, and lifecycle round-trip while raw paths and opaque native material remain absent.
- **AC-02 — Project persistence:** Independent native Project JSONL restart/replay tests prove atomic optimistic commits, deterministic cataloging, tombstones, partial-tail recovery, corruption isolation, sanitized failures, and no session-namespace regression; web publishes no Project stream.
- **AC-03 — Session migration:** Supported v1/v2 session fixtures restore as unassigned without read-time rewrite; v3 Project membership survives restart/catalog projection, and membership conflicts cannot overwrite any existing session field.
- **AC-04 — Root/grant truthfulness:** Desktop grants are separate and active only after requested access is acknowledged and freshly revalidated; mobile roots are typed app-owned identities without fake external grants; missing/stale/revoked/corrupt/unsupported/unverifiable state fails closed without token/path leakage.
- **AC-05 — Path/root security:** Automated negatives deny desktop overlap, files/link roots, mobile sandbox escape/pre-existing unknown roots, traversal, separator/absolute/alternate-path injection, canonical or symlink/junction escape, cross-Project/stale handles, Project switches, and writes through additional grants before I/O.
- **AC-06 — Creation atomicity:** Desktop attach/create and mobile sandbox success publish one empty restart-safe Project only after its typed root commits/revalidates; name/target/directory collision, picker/folder cancellation, storage failure, cancellation races, and crash-orphan rollback create no false Project or active access and delete only an unchanged empty staged root.
- **AC-07 — Safe deletion:** Confirmed deletion is restart-idempotent and fail-closed, retains every chat/transcript/user file under `Без проекта`, and does not tombstone/claim success until healthy memberships are cleared; cancellation/conflict/failure behavior matches the contract.
- **AC-08 — Ownership projection:** Real catalog data renders every chat exactly once under its Project or recoverable `Без проекта`; only an active healthy selected Project admits a scoped chat, and unresolved membership grants no filesystem authority.
- **AC-09 — Functional milestone:** Linux/Windows/macOS desktop Projects and Android/iOS sandbox Projects can be created/selected with chats across restart; all platforms retain usable unassigned chats and distinct sanitized loading/empty/access/corruption/persistence/deletion states.
- **AC-10 — Selected support matrix:** Linux/Windows/macOS pass full attach/create/additional adapter contracts, including macOS security-scoped stale/revoked fail-closed tests; Android/iOS create only app-owned roots with external controls/calls absent; web shows unsupported UI and performs no Project-related write.
- **AC-11 — Accessibility/responsiveness:** Keyboard, focus, semantics, minimum-target, and 390×844 tests cover Project creation/navigation/deletion/error paths without clipping, path/token leakage, or a competing `final-01` redesign.
- **AC-12 — Scope boundary/checks:** No agent filesystem tool or project-file I/O exists beyond contracted root-directory provisioning/rollback; approved design/provider/unrelated-change paths remain untouched, and targeted tests plus `dart format .`, `flutter analyze`, and `flutter test` pass on the recorded implementation fingerprint.
