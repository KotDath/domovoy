# domovoy — финальный HTML-макет

Статус: **дизайн одобрен пользователем 19 сентября 2026**, финальная полировка
выполнена в рамках его поручения. Версия: `final-01`. Это визуальная база для
отдельной продуктовой реализации, не готовая Flutter-функциональность.

Пользователь: «в целом мне вот эта версия очень нравится. Я бы её одобрил»;
поручение: найти дизайнерский скилл, подштриховать и зафиксировать финальный макет.
База утверждения — v05a; финальная полировка сохраняет её компоновку и поведение.

## Открыть

http://localhost:8765/?v=final-01

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory design/redesign-preview
```

Можно открыть `index.html` напрямую. Зависимости и сборка не нужны.

## Зафиксированный дизайн

- Desktop shell с левой навигацией. Простой английский wordmark `domovoy`.
- Верхний пункт «Новый чат»; секции «Проекты» и «Чаты» с плюсами.
  Проекты содержат вложенные чаты; legacy-чаты — «Без проекта».
  Плюс проекта создаёт чат именно в нём, верхний пункт и плюс «Чаты» —
  в текущем проекте либо без проекта по текущему контексту.
- Компактные строки, outline-папки, нейтральное выделение выбранного чата;
  без вертикальных направляющих и видимых счётчиков.
- Header: иконка папки + название чата, без slash. Название проекта и root
  показываются по нажатию на папку.
- Пользовательское сообщение — компактный raised block справа; ответ —
  свободная проза. Вместо имени/модели над ответом — «Работал N с/мин».
- Composer снизу, выровнен по ширине ленты. Справа: context ring,
  модель, reasoning, отправка. Плюс слева — демонстрационный вход в контекст.
- Контекст — компактный немодальный popover вверх от индикатора: used/limit,
  заполнение, состав в токенах. Неизвестное — «—», полный объём может отличаться.
- Модель — каскад: провайдеры слева, модели справа, hover/click/focus.
  Reasoning — отдельное меню вверх. Escape и клик вне закрывают меню.
- Полноценный workspace провайдеров: список/детали, модели, состояние подключения.
  Ключи не показываются и не вводятся в макете.
- Создание проекта: имя, отдельная root-папка, дополнительные папки read-only
  по умолчанию. Макет не выдаёт доступ и не заявляет о выданных разрешениях.
- Usage: вход/выход, неизвестный cache/reasoning — «—». Стоимость — «—»,
  тарифы отсутствуют.
- Theme: System по умолчанию, Dark/Light доступны. На narrow sidebar за меню.

## Визуальная система

| Роль | Dark | Light |
| --- | --- | --- |
| Canvas | #202225 | #f8f7f4 |
| Sidebar | #191b1e | #efeeea |
| Raised | #282b30 | #fffefa |
| Border | #363940 | #ddddd7 |
| Text | #e3e4e8 | #292d35 |
| Accent | #aabafb | #4d61a7 |

Системный sans-serif, основной текст 13–15px, спокойная иерархия,
низкоконтрастные 1px границы, радиусы 10–16px у поверхностей.
Лента ~700px; sidebar 270px. Видимый keyboard focus, restrained periwinkle.
Главный акцент — текст и рабочий диалог; без декоративных палитр и слоганов.
Финальная полировка: выравнивание composer/ленты, единые utility-иконки,
читаемые подписи, focus, selected settings и доступное обозначение текущего чата.

Применён [frontend-design от Anthropic](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md).
Скилл прочитан из официального репозитория, глобально не устанавливался.
Его рекомендации о сдержанности, типографике, содержательных подписях и
визуальной самопроверке применены в рамках уже одобренной композиции.

## Демонстрационные ограничения

Нет сети к провайдерам, чтения файлов, хранения секретов и постоянного состояния.
Данные, пути, модели и usage — примеры. Состояние сбрасывается при reload.
Изначальные чаты используют один пример переписки. Новые чаты — пустые;
введённый текст показывается буквально. Отправка запускает шестисекундную
демонстрацию с таймером и заранее написанным ответом; повторный клик останавливает.
Навигация во время демо завершает его — это ограничение прототипа.
Копирование/проверка подключения показывают объясняющее уведомление.

## Граница будущей реализации

Дизайн принят; Flutter, тесты, OpenSpec, зависимости и platform-файлы не изменены.
Далее — отдельное OpenSpec-планирование и согласованная Light-реализация.

В текущем Flutter сообщения — SelectableText, Markdown renderer отсутствует.
HTML-пример показывает headings/lists/emphasis/links/inline и fenced code.
Выбор renderer, безопасные ссылки и streaming-поведение определяются при
планировании. Arbitrary HTML не предполагается; таблицы/task lists не согласованы.
Числа и демонстрационный каталог не являются контрактом runtime. Реальные
provider/reasoning capabilities, context composition и permissions нужно связать
с состоянием приложения; pricing не выдумывать.
