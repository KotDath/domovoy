# Domovoy

Personal AI assistant built with Flutter.

## Linux development

The application stores an optional DeepSeek API-key override with Secret
Service. Install the `libsecret` runtime and development packages before
building the Linux desktop app. On Debian and Ubuntu:

```sh
sudo apt install libsecret-1-0 libsecret-1-dev
```

At runtime, Domovoy first uses the API key saved in its settings and otherwise
falls back to the `DEEPSEEK_API_KEY` process environment variable.

## День 3 — сравнение стратегий рассуждения

В эксперименте одна и та же логическая задача была отправлена четырьмя
способами: напрямую, с инструкцией рассуждать по шагам, через предварительно
сгенерированный промпт и через группу независимых экспертов с отдельным
синтезатором. Нативный thinking-режим модели во всех запросах был выключен,
поэтому сравнивались именно способы построения промпта.

### Результаты

- Прямой запрос дал правильную итоговую таблицу, но в рассуждении была
  логическая ошибка: нахождение Глеба и кофе в одном доме было ошибочно принято
  за конфликт. Неподходящая ветка оказалась отброшена по неверной причине.
- Пошаговый запрос также дал правильный ответ. Его было проще проверять по
  отдельным условиям, хотя ответ получился значительно длиннее.
- Сгенерированный промпт привёл к правильному результату и более явной проверке
  единственности, но не устранил все локальные неточности в доказательстве.
- В экспертной группе отдельные API-вызовы дали разные результаты: большинство
  экспертов нашло правильную таблицу, а один эксперт ошибочно решил, что задача
  не имеет решения. Это подтвердило, что независимые ответы действительно
  создают полезное разнообразие, а не имитируют его внутри одного сообщения.
- Синтезатор выбрал правильный результат на основе экспертных ответов, но его
  объяснение ошибки меньшинства тоже оказалось не полностью точным. Настоящая
  ошибка состояла в смешении независимых категорий: наличие Глеба в доме не
  мешает тому же дому иметь напиток «чай».

Во время нескольких прогонов модель в целом корректно выполняла инструкции и
приходила к правильному финальному ответу. Однако этот опыт показывает, что
нельзя оценивать качество только по итогу: корректный ответ может содержать
ошибочное промежуточное обоснование. Детерминированный решатель и проверки
условий помогают обнаруживать такие непредвиденные результаты.

### Практический опыт

В практических задачах экспертный синтез особенно полезен там, где существует
несколько обоснованных точек зрения. Например, при проектировании архитектуры
программного обеспечения отдельные эксперты могут независимо рассмотреть:

- границы модулей и общую структуру системы;
- производительность, отказоустойчивость и эксплуатацию;
- безопасность, тестируемость и риски сопровождения.

После этого синтезатор сопоставляет предложения, находит противоречия и формирует
единое архитектурное решение с явно указанными компромиссами. Такой подход не
гарантирует правильность автоматически, но снижает риск пропустить важное
ограничение и делает принятые решения лучше обоснованными.

### Вывод

Для этой небольшой задачи прямой запрос оказался самым экономичным, а пошаговый
— самым удобным для ручной проверки. Группа экспертов требует четырёх
API-вызовов и поэтому оправдана не всегда, но повышает устойчивость на сложных и
важных задачах: ошибка одного ответа может быть обнаружена другими экспертами.
Экспертный синтез следует использовать вместе с независимым валидатором, а не
вместо него.
