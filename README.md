# Domovoy

Personal AI assistant built with Flutter.

## Linux development

The application stores an optional DeepSeek API-key override with Secret
Service. Install the `libsecret` runtime and development packages before
building the Linux desktop app. On Debian and Ubuntu:

```sh
sudo apt install libsecret-1-0 libsecret-1-dev
```

At runtime, Domovoy first uses the API key saved in its settings and otherwise
falls back to the `DEEPSEEK_API_KEY` process environment variable.

## День 4 — температура генерации

В эксперименте один и тот же запрос с просьбой объяснить принципы SOLID был
отправлен модели DeepSeek с температурами `0.0`, `0.7` и `1.2`. Нативный
thinking-режим был выключен, а `top_p` не задавался, поэтому изменялась только
температура. Каждый вариант выполнялся отдельным API-вызовом без истории
диалога.

Температура управляет случайностью выбора следующего токена, а не количеством
знаний или уровнем интеллекта модели. При низком значении наиболее вероятные
продолжения получают больший приоритет, поэтому ответы обычно стабильнее. При
повышении температуры модель чаще выбирает менее вероятные варианты, что
увеличивает разнообразие формулировок и примеров, но также повышает риск
неточностей и отклонения от задачи.

### Наблюдения

- Во всех трёх ответах DeepSeek правильно расшифровал SOLID, сохранил порядок
  принципов и передал их основное содержание.
- Отличия проявились прежде всего в подаче: менялись примеры, объём объяснений,
  метафоры и отдельные термины.
- Более вариативные ответы использовали дополнительные аналогии и менее
  очевидные формулировки, но в них также встречались шероховатости оформления и
  спорные детали.
- При температуре `0.0` повторный запрос к DeepSeek вернул ответ, полностью
  совпавший с предыдущим. В рамках этого практического прогона нулевая
  температура обеспечила воспроизводимый результат.
- Один результат на каждую температуру позволяет показать различия, но не
  описывает всё вероятностное распределение модели. Для статистического
  сравнения нужно выполнить несколько прогонов каждого значения.

### Практический опыт

При работе с реальными задачами по программированию повышенная температура
иногда уводила модель в сторону от исходных требований. Она могла предлагать
лишние изменения, выбирать неожиданную архитектуру или добавлять решение
проблем, которых не было в запросе. Поэтому для написания кода, исправления
ошибок, рефакторинга и технической документации предпочтительна низкая
температура: в таких задачах важнее точность и воспроизводимость.

Умеренные и высокие значения полезны в задачах, где требуется разнообразие:
мозговой штурм, поиск нескольких архитектурных вариантов, нейминг, сценарии и
творческие тексты. Полученные идеи при этом необходимо дополнительно проверять.

### Вывод

Эксперимент с DeepSeek показал, что температура регулирует вариативность, а не
качество ответа напрямую. Температура `0.0` дала повторяемый ответ один в один;
`0.7` и `1.2` сделали формулировки разнообразнее, но не гарантировали улучшения
содержания. Чем строже требования к коду и фактической точности, тем полезнее
низкая температура. Более высокую температуру стоит выбирать осознанно, когда
ценность новых вариантов превышает риск ухода от исходной задачи.
