## Где код

- SDK клиента и серверов — `mcp_dart` из корневого `pubspec.yaml`.
- Подключения stdio, Streamable HTTP, handshake и каталог —
  `lib/infrastructure/mcp/`, `lib/features/mcp/`.
- Четыре наших сервера — `lib/infrastructure/mcp/servers/{arxiv,digest,library,automation}/`.
- Встраивание клиента в агента и разрешения — `lib/core/agents/mcp_tools.dart`,
  `lib/app.dart`.
- Планировщик, JSONL и исполнение — `lib/core/automation/`,
  `lib/infrastructure/automation/`, `lib/features/tasks/`.
- Сценарии проверки — `test/core/agents/mcp_tools_test.dart`,
  `test/infrastructure/mcp/`, `test/core/automation/`.

## Повторение сценария

1. Настройте DeepSeek в разделе «Провайдеры», используя защищённое хранилище
   приложения или `DEEPSEEK_API_KEY` для локального запуска.
2. Откройте «MCP-серверы». Четыре встроенных подключения должны иметь статус
   «готово». Для внешнего примера добавьте
   `https://mcp.deepwiki.com/mcp` как Streamable HTTP без токена.
3. В новом чате через «Инструменты MCP» разрешите `arxiv.search_papers`,
   `digest.summarize_papers` и `deepwiki.ask_wiki_question`. Попросите найти
   статью, передать её в Digest и сопоставить с ответом DeepWiki по
   `langchain-ai/langchain`. Агент может вызвать независимые arXiv и DeepWiki
   в любом порядке; Digest должен следовать за результатом arXiv.
4. Для дня 19 в «Задачи» создайте шаблон arXiv и нажмите «Запустить сейчас».
   Откройте трассу запуска и запись в «Библиотеке». Там должна быть сохранена
   сводка с `sourceScope=abstract` и ссылкой на arXiv.
5. Для дня 18 задайте cron `* * * * *`, оставьте приложение открытым минимум
   пять минут и смотрите историю запусков. Повторить создание задачи через
   агента можно вызовом `mcp_automation__create_task`; предложение надо
   подтвердить в разделе «Задачи».

На Android и Авроре встроенные серверы работают локально в процессе
приложения. На desktop каждый встроенный MCP **HTTP endpoint** запускается в
отдельном дочернем процессе; его PID отображается в списке подключений.
Обработчики инструментов и их общее состояние остаются в процессе Flutter, а
дочерний процесс пересылает MCP-запросы по loopback. Это важно при оценке
изоляции: сейчас отдельный процесс держит транспорт, а не всю бизнес-логику.
Для запуска из исходников нужен `dart` в PATH и корень репозитория как рабочий
каталог. Для распространяемой desktop-сборки нужно положить исполняемый файл
`domovoy_mcp_sidecar` (на Windows с `.exe`) рядом с исполняемым файлом
Domovoy. Его можно получить командой:

```sh
dart compile exe tool/domovoy_mcp_sidecar.dart -o domovoy_mcp_sidecar
```

Встроенный клиент и сервер работают только при запущенном приложении.
Планировщик на телефоне останавливается в фоне и продолжает при возврате;
настоящий режим 24/7 при закрытом приложении пока не реализован. Устройства
не синхронизируют расписания и библиотеку.
