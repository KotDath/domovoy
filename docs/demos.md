# Демонстрации дней 6–8

Запуск обычного приложения: `flutter run -d linux`. Ключ DeepSeek берётся из `DEEPSEEK_API_KEY` или из настроек приложения. В списке моделей найдите DeepSeek Flash; кнопка обновления моделей находится в настройках провайдеров.

## День 6: агент и реальный API

1. Откройте новый чат и выберите DeepSeek Flash.
2. Отправьте: «Придумай три коротких названия для приложения записи в мастерскую».
3. Покажите поступающий ответ, выбор модели и сведения о токенах.
4. В коде покажите `AgentDefinition`, `runtime.agent(definition)` и сессию: запрос выполняет отдельный агент, HTTP скрыт за адаптером провайдера.

## День 7: перезапуск с историей

1. В новом чате отправьте: «Мой проект называется Север, бюджет 150000 рублей, срок 15 ноября. Запомни это».
2. Дождитесь конца ответа. Закройте приложение полностью.
3. Запустите снова и выберите тот же чат в истории.
4. Отправьте: «Как называется мой проект, какой бюджет и срок?».
5. Покажите ответ и накопленные токены: история и учёт восстанавливаются из JSONL.

Для браузерной проверки можно перезагрузить страницу: создаётся новый runtime, история читается из хранилища браузера. Для записи видео предпочтителен полный перезапуск Linux-приложения.

## День 8: короткий, длинный, переполнение

Отдельная точка запуска: `flutter run -d linux -t lib/day08_main.dart`.

1. Выполните короткий запрос и покажите input/output/overall из API.
2. Выполните длинный сценарий; сравните размер следующих запросов и сумму расхода.
3. Нажмите кнопку переполнения. Она создаёт заведомо большой запрос, не заставляя вручную вставлять мегабайты текста.
4. Покажите исходную ошибку DeepSeek о превышении контекста. Ошибочный запрос без usage отображается как неизвестный расход, а не ноль или оценка.

В этом диагностическом запуске нет автоматического сжатия и повторной отправки. В обычном приложении штатное управление контекстом сохраняется.

Input включает попадания в кэш, output включает reasoning. Cache hit % = cache read / input. Reasoning и видимый вывод — составные части output; их не прибавляют к общему расходу повторно. «Вся история» в учёте — сумма физических API-вызовов, включая повторную отправку истории; это не оценка количества токенов в сохранённом тексте.

## Проверка в браузере без ключа в сборке

Собирайте каждую точку входа в отдельной папке за пределами Flutter `build/` и копируйте завершённый результат перед следующей сборкой. В нашем окружении последовательные сборки в `build/web` и `build/day08-web` очищали общие ресурсы предыдущей страницы, включая `FontManifest.json` и шрифт иконок.

```sh
flutter build web --no-web-resources-cdn -t lib/live_web_main.dart -o /tmp/domovoy-normal-web-build
python3 -c 'import shutil; shutil.copytree("/tmp/domovoy-normal-web-build", "/tmp/domovoy-normal-web-served", dirs_exist_ok=True, symlinks=False)'
flutter build web --no-web-resources-cdn -t lib/day08_web_main.dart -o /tmp/domovoy-day08-web-build
python3 -c 'import shutil; shutil.copytree("/tmp/domovoy-day08-web-build", "/tmp/domovoy-day08-web-served", dirs_exist_ok=True, symlinks=False)'
```

Перед запуском убедитесь, что в каждой копии есть `assets/FontManifest.json` и `assets/fonts/MaterialIcons-Regular.otf`. Запустите relay обычного приложения: `python3 tool/live_proxy.py --directory /tmp/domovoy-normal-web-served --port 8765`, затем откройте `http://localhost:8765`. Для диагностики запустите второй relay: `python3 tool/live_proxy.py --directory /tmp/domovoy-day08-web-served --port 8766` и откройте `http://localhost:8766`. Настоящий ключ остаётся в окружении процесса Python; браузерная сборка содержит только публичный маркер.
