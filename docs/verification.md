# Проверка дней 6–8

Проверено 13 сентября 2026 года. Сборка использует 30 профилей API-ключей; реальный сетевой smoke-тест выполнен для DeepSeek. Остальные профили покрыты контрактом адаптера и фикстурами там, где они есть, но не объявляются проверенными с настоящими ключами. OpenCode Zen/Go отложены из-за разных API-маршрутов у разных моделей.

| Проверка | Результат |
|---|---|
| `flutter analyze --no-pub` | Без замечаний |
| `flutter test --reporter expanded` | 462 теста прошли после исправления офлайн-кэша, переключения модели и строки суммы истории |
| `flutter build linux --debug` | Успешно |
| `flutter build web --no-web-resources-cdn -t lib/live_web_main.dart -o build/web` | Успешно |
| `flutter build web --no-web-resources-cdn -t lib/day08_web_main.dart -o build/day08-web` | Успешно после строки суммы |
| `openspec validate add-provider-discovery-and-api-usage --strict` | Изменение валидно |

`flutter test tool/live_deepseek_test.dart --reporter expanded` с реальным `DEEPSEEK_API_KEY` прошёл через production `AgentRuntime`, поток SSE, сохранение JSONL и новый runtime после перезапуска. Из API получены пары «ввод / вывод / всего»: DeepSeek Flash 41 / 17 / 58; после восстановления 86 / 17 / 103; с reasoning 146 / 29 / 175, включая 27 reasoning-токенов; DeepSeek Pro 133 / 3 / 136. Учёт сессии совпал с сообщениями SSE. Отдельная проверка повторённого запроса показала ввод 3471, чтение кэша 3328, некэшированный ввод 143, вывод 2, всего 3473.

Ручная проверка обычного браузерного приложения через локальный relay показала сохранённые факты после перезагрузки, выбор модели, изоляцию ключей и видимые API-значения без оценки контекста. Один ответ Flash: ввод 59, вывод 138, всего 197; reasoning 113. После перезагрузки история сохранилась, а следующий ответ Pro дал 127 / 3 / 130.

Последующий ручной прогон выявил, что переход с Flash или восстановленного Pro на Claude Sonnet 4.6 при отсутствующем свежем provider usage запускал подготовку даже для короткой истории и блокировался результатом `NoChange`. Исправление использует внутреннюю оценку только для решения о необходимости подготовки при отсутствии API-измерения. Две регрессионные проверки production stack проходят после обновления каталога: пустой чат Flash → Claude и восстановленный из JSONL чат Pro с историей → Claude. Оба перехода не создают лишнего запроса к провайдеру. Ручной повтор обоих сценариев в новом браузерном билде прошёл: модель сменилась, история сохранилась, а для native reasoning показано отключённое «По умолчанию».

Отдельная normal web-сборка в `/tmp` включила `FontManifest.json` и `MaterialIcons-Regular.otf`; повтор через relay подтвердил иконки, сохранённую после перезагрузки модель Claude и тот же отключённый native control. Последовательные сборки в двух подпапках Flutter `build/` оставляли пустые каталоги ресурсов, поэтому команды для воспроизводимого браузерного демо в [руководстве](demos.md) используют внешние каталоги и стабильные копии.

Независимая проверка выявила один дефект офлайн-перезапуска: кэшированный новый ID Perplexity без собственного `/models` пропадал, если `models.dev` был недоступен. После исправления тест восстанавливает ID из кэша при ошибке сети и удаляет его только после успешного обновления метаданных, в которых ID уже нет. Повторный полный прогон дал 462 успешных теста; Linux и обычная web-сборка прошли. Платный live-запрос DeepSeek и ручной сценарий дня 8 не повторялись, поскольку их путь не изменился.

При разработке дня 9 обнаружена отдельная коллизия ID после перезапуска: новый runtime начинал нумерацию сообщений с прежних `message-*`, и добавление к восстановленной JSONL-истории могло завершиться ошибкой уникальности `AgentTranscript`. Production builder теперь назначает случайное пространство ID каждому новому runtime; прямой `AgentIdFactory()` сохраняет прежний формат для существующих клиентов и тестов. Новая регрессионная проверка создаёт legacy-сессию, закрывает runtime, восстанавливает её свежим production stack и успешно добавляет следующий запрос без повторения ID. Это исправление действует на обычные дни 6–8; политика сжатия и транспорт провайдера не менялись.

После этой правки прошли 19 целевых composition-тестов и весь набор из 464 тестов. `flutter analyze` не нашёл замечаний; `dart format .` обработал 167 файлов без изменений. Сборки Linux debug и обычного web entry прошли; внешняя web-сборка содержит FontManifest и Material Icons. OpenSpec strict validation и diff check прошли. Повторный платный вызов DeepSeek не требовался: исправлялась только генерация локальных ID.

Отдельная страница дня 8 использовала настоящий DeepSeek. Короткий запрос: 25 / 4 / 29. В заключительном длинном прогоне три физических вызова дали 34 / 17 / 51, 666 / 24 / 690 и 707 / 14 / 721. Строка истории показала точную сумму: ввод 1407, вывод 55, всего 1462. Последний вызов сообщил 512 токенов чтения кэша, то есть 72,4% от ввода. До первого вызова история показывала «—», поскольку API ещё ничего не сообщил. В отдельном прогоне кнопка переполнения отправила один POST и получила HTTP 400. Страница показала исходный текст API: “This model's maximum context length is 1048576 tokens. However, you requested 1100016 tokens (1100015 in the messages, 1 in the completion). Please reduce the length of the messages or completion.” У ошибочного вызова нет usage; все значения отображены как «—». Повторного запроса и автоматического сжатия в диагностическом режиме не было.

Anthropic Messages и Gemini generate-content поддерживают текстовый поток и факты usage, сообщённые API. Native tool turns и явные переключатели thinking не предлагаются до проверки подписей продолжения и настроек конкретной модели. Отсутствующие лимиты новых моделей не выдаются за известные. Внутренний оценщик контекста обычного приложения сохраняется для штатного сжатия, но его значения не показываются как расход API.
