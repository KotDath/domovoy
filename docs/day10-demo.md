# День 10: окно, явные факты и ветки

Эта ветка демонстрирует три разных способа передать историю одному и тому же DeepSeek Flash через настоящий `AgentRuntime`. Сценарий из 14 запросов находится в `assets/day10_scenario.json`. Переключатель выбирает стратегию для кнопки «Шаг выбранной стратегии»; выбор сохраняется после reload. «Следующий шаг» продвигает три стратегии до ближайшего общего шага, а «Все 14 шагов» завершает одинаковый сценарий для каждой. Ответы и таблица расхода появляются только после реальных вызовов API. Полный сценарий делает 42 вызова, плюс до четырёх вызовов при проверке ветвей A/B.

Для нативного приложения API-ключ берётся из обычного безопасного хранилища или переменной окружения `DEEPSEEK_API_KEY`:

```sh
flutter run -d linux -t lib/day10_main.dart
```

Для браузерной записи ключ остаётся только в локальном Python-релее. Сборка живёт вне общего Flutter `build/`, иначе следующая сборка может заменить её общие шрифтовые assets:

```sh
flutter build web --no-web-resources-cdn --target lib/day10_web_main.dart --output /tmp/domovoy-day10-web
DEEPSEEK_API_KEY=... python3 tool/live_proxy.py --directory /tmp/domovoy-day10-web --port 8771
```

Откройте `http://localhost:8771`. Многоточие в команде заменяется настоящим ключом **только на машине релeя**; не помещайте ключ в браузерный код, скриншот или журнал. Проверка `assets/FontManifest.json` и `assets/fonts/MaterialIcons-Regular.otf` в итоговой папке подтверждает, что шрифты остались со сборкой.

Порядок короткой записи: выберите одну стратегию и выполните отдельный шаг, затем запустите общий сценарий. Раскройте любой из 14 запросов, посмотрите итоговые ответы рядом с восемью контрольными фактами, факты во второй стратегии и реальные суммы API. Когда стратегия «Ветвление» завершит шаг 8, появляются ветви A/B. Нажмите «Добавить в A» (лист ожидания) и «Добавить в B» (семейные записи), затем «Проверить A/B». Последующий запрос не подсказывает правильный ответ и просит назвать только решение своей ветви. Переключите ветви, перезагрузите страницу и покажите восстановленные историю, lineage, факты и ledger. Кнопка «Следующий шаг в выбранной ветке» продолжает общий сценарий из checkpoint независимо от другой ветви.

Стратегии отличаются так:

| Стратегия | Что получает очередной запрос | Что остаётся в интерфейсе |
| --- | --- | --- |
| Скользящее окно | Только две последние завершённые пары | Полная видимая история для сравнения |
| Явные факты | Те же две пары и карта поддерживаемых полей `Ключ: значение` | Карта, где `Бюджет: 150000` заменяет 120000 до генерации |
| Ветвление | Полная история собственной ветви | Родитель, checkpoint 8 и только новый расход A/B |

Распознавание фактов намеренно детерминированное и узкое: поддерживаются проект, бюджет, срок, уведомления, регион данных, онлайн-оплата, длительность и отмена из явно помеченных пользовательских фраз. Это не универсальная семантическая память. Ветки являются копиями истории на шаге 8; они не получают сообщения друг друга. Исторические вызовы родителя указаны в lineage, но не суммируются вторично в расход ветки.

Восемь контрольных фактов — это критерий чтения ответа, а не предзаполненный ответ модели. Сравнивайте реально выданное итоговое ТЗ, включая «неизвестно» и ошибки, не присваивая автоматическую оценку. API-суммы используют включительные ввод/вывод/всего и данные о кэше только из физического ledger. `—` означает, что значение не сообщено; частичная сумма помечается `+`. Дополнительная системная карта фактов и полная ветка могут повысить входной расход, поэтому экономия токенов не гарантирована. По удобству окно проще, явные факты требуют поддерживать структуру, а ветви удобны для независимых вариантов, но сохраняют длинный контекст.

После ручного живого прогона запишите наблюдаемые числа и ответы отдельно: расходы каждой стратегии, число правильных из восьми фактов **по фактическому ответу**, проверки A/B, reload и ошибки. Не заменяйте эти наблюдения прогнозом или результатом соседней ветки Day 9.

Ручной браузерный прогон общего сценария на DeepSeek Flash дал такие **наблюдённые**, а не гарантированные результаты:

| Стратегия | Вызовы | Ввод API | Вывод API | Всего API | Кэш чтение | Факты итогового ответа |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Скользящее окно | 14 | 9196 | 1407 | 10603 | 512 | 0/8; модель ответила «неизвестно» |
| Явные факты | 14 | 11318 | 2000 | 13318 | 256 | 8/8; действующий бюджет только 150000 |
| Ветвление (основная история) | 14 | 20275 | 1269 | 21544 | 17280 | 8/8 |

Окно оказалось дешевле по токенам, но потеряло все восемь проверяемых решений. Явные факты сохранили их с меньшим общим расходом, чем полная история, ценой ограниченного формата полей и их поддержки. Полная ветка передала длинную историю и тоже удержала решения, но потратила больше вводных токенов. Это описание одного прогона, а не обещание качества для других диалогов.

После checkpoint ветка A сделала два **новых** вызова: 3090 ввод, 49 вывод, 3139 всего. Она назвала только лист ожидания. Ветка B: 3072 ввод, 44 вывод, 3116 всего; она назвала только семейные записи. В каждой ветке восемь унаследованных вызовов показаны в lineage и исключены из новых сумм. Переключение B→A сохранило ответ и расход A; reload восстановил все три итоговые суммы, шаг 14/14, активную A и её расход. Числа и краткие ответы записаны в `/tmp/domovoy-evidence/day10-live.json` на машине проверки.

В отдельной проверке переключателя один шаг продвинул только выбранное окно, затем только выбранные факты; выбор фактов пережил reload. В режиме ветвления checkpoint появился сразу после его собственного восьмого ответа, пока две другие стратегии оставались на первом шаге. Это подтверждает независимое управление шагами, а не только общий автоматический прогон.
